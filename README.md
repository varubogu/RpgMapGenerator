# RpgMapGenerator

RPGツクールMV/MZ向けのダンジョンマップを**ビルド時に**自動生成するツールです。

ゲーム実行中にランダム生成するのではなく、制作時にマップデータ(`MapXXX.json`)を
作って固定します。手作業でダンジョンを組む手間を省きつつ、生成後はエディタで自由に手直しできます。

- 入口・出口・宝箱の位置や中身を指定できる。指定しなかった項目は自動で決まる
- 「壁に囲まれて取れない宝箱」「宝箱が通路を塞いで先に進めない」といった破綻を検証し、通ったものだけを出力する
- シードを固定すれば何度実行しても同じマップになる
- MV/MZのプロジェクトに直接書き込める(マップ一覧への登録込み)

```
########################################
##S.....################################
##......##........######################
##......##........##############..C..C.#
##................##############.......#
##########C.......########.............#
###########.############....############
#########...................############
######.......#########.#....############
####.....###########.....###..C...######
####.....###########..............######
############################.....G######
########################################
# 壁  . 床  S 入口  G 出口  C 宝箱
```

## 使い方

Node.js 20 以上が必要です。

```sh
npm install
npm run build

# 生成結果をテキストで確認する
node dist/presentation/cli.js generate examples/basic.yaml --format ascii

# ツクールのプロジェクトに書き込む(エディタは閉じておく)
node dist/presentation/cli.js generate examples/fixed-points.yaml --project path/to/MyGame
```

| オプション             | 内容                                                          |
| ---------------------- | ------------------------------------------------------------- |
| `--seed <値>`          | シードを上書きする                                            |
| `--format <形式>`      | `rpgmaker`(既定) / `json`(エンジン非依存の中間形式) / `ascii` |
| `--out <ファイル>`     | 出力先ファイル。省略時は標準出力                              |
| `--project <フォルダ>` | ツクールのプロジェクトフォルダ。`data/` に直接書き込む        |
| `--map-id <番号>`      | 書き込むマップID。省略時は空いている最小のID                  |
| `--preview`            | 生成結果をテキストで表示する                                  |

### ツクールへの取り込み

`--project` を付けると `data/MapXXX.json` を書き出し、新規IDなら `data/MapInfos.json` にも登録します。

- **エディタを閉じてから実行してください。** 開いたままだと、エディタの保存時に上書きされます
- 既存のマップIDを指定すると、そのマップを上書きします(手直しした内容は失われます)。プロジェクトはバージョン管理かバックアップをしておいてください
- 既定値は標準の「ダンジョン」タイルセット(ID 4)を想定しています。別のタイルセットを使う場合は `tiles` を指定してください
- **壁の通行設定はタイルセット側で決まります。** データベースのタイルセットで、壁の上面・側面が通行不可(×)になっていることを確認してください
- 入口・出口の場所移動先を設定で指定しなかった場合は、注釈だけのイベントを置きます。エディタで移動先を設定してください

`--project` を使わない場合は、`--out` で出力した JSON を `data/MapXXX.json` として置き、
エディタで同じIDのマップを作成済みにしておけば読み込まれます。

## 設定ファイル

YAML または JSON で書きます。必須なのは `size` だけです。完全な例は [`examples/`](examples) にあります。

```yaml
seed: castle-b1 # 省略するとランダム(実行時に表示される)
size: { width: 50, height: 36 } # 7〜256

rooms: # すべて省略可
  count: 9 # 部屋数の目安
  minSize: 4
  maxSize: 9
  loopChance: 0.25 # 回り道の通路を足す確率

entrance: # 省略すると位置はおまかせ
  x: 3
  y: 3
  transfer: { mapId: 1, x: 10, y: 8, direction: 2 }

exit: {} # おまかせ(入口から最も遠い場所)。false で出口なし

chests: # 省略すると個数も位置もおまかせ。数値なら個数だけ指定
  - { x: 45, y: 30, item: 7 } # 位置と中身を指定
  - { gold: 1000, message: "大金だ！" } # 位置はおまかせ
  - {} # すべておまかせ

output:
  format: rpgmaker
  path: out/Map.json # 設定ファイルからの相対パス
  rpgmaker:
    target: mz # mv | mz
    project: ../MyGame # 指定するとプロジェクトに直接書き込む
    mapId: 5 # 毎回同じマップを上書きする場合
    mapName: 城 地下1階 # マップ一覧での名前
    displayName: 城の地下 # ゲーム内の表示名
    tilesetId: 4
    tiles:
      floor: { sheet: A2, index: 0 } # タイルセット画像内の通し番号(左上が0)
      wallTop: { sheet: A4, index: 0 } # 壁の上面
      wallSide: { sheet: A4, index: 8 } # 壁の側面
      entrance: { sheet: B, index: 20 } # 入口マスに重ねる装飾(省略可)
    autoShadow: true
    regions: { floor: 1, wall: 2 } # リージョンIDを書き込む(省略可)
    messages:
      gold: "{amount}\\Gを手に入れた！"
      item: "アイテムを手に入れた！"
```

座標は左上を `(0, 0)` とし、外周1マスは必ず壁になります。位置を指定できるのは `x=1〜幅-2`、`y=1〜高さ-2` です。

## 破綻させない仕組み

1. **構造で保証する**: 部屋同士を全域木でつなぐため、床は必ずひと続きになります。位置指定された宝箱は周囲を床にして、迂回できるようにします
2. **配置時に確かめる**: 宝箱を自動で置くときは、置いた後も全体が成立する場所だけを選びます
3. **最後に検証する**: 生成とは独立した検証を必ず通します。宝箱を通行不可の障害物とみなした上で、次を確認します
   - 外周が壁で閉じている
   - 入口・出口・宝箱が床の上にあり、重なっていない
   - 入口から出口に到達できる
   - すべての宝箱に隣接できる
   - 入口から到達できない床がない

検証に通らなければシードから導いた別の乱数列で作り直し、規定回数で成立しなければエラーで終了します。破綻したマップが出力されることはありません。

## 構成

```
src/
├── domain/          地形・乱数・生成アルゴリズム・配置・検証(外部ライブラリに依存しない)
├── application/     生成のユースケース、アルゴリズムの登録、エクスポータのインターフェース
├── infrastructure/  ツクール形式への変換、設定ファイルの読み込み、各種エクスポータ
├── presentation/    CLI
└── index.ts         ライブラリとしての公開API
```

依存は外側から内側への一方向です。`domain` と `application`、およびマップデータの組み立ては
Node.js 固有のAPIを使っていないため、ブラウザでもそのまま動かせます(Web UI を足す場合の土台になります)。

### 拡張するには

- **生成アルゴリズムを足す**: `LayoutGenerator`(`src/domain/generator.ts`)を実装し、`GeneratorRegistry` に登録します。配置と検証は共通なので、地形を作ることだけに集中できます
- **出力形式を足す**: `DungeonExporter`(`src/application/exporter.ts`)を実装します。入力はエンジン非依存の `Dungeon` です
- **セルの種類を足す**: `Cell`(`src/domain/grid.ts`)に種別を追加し、エクスポータ側で対応するタイルを割り当てます

## 開発

```sh
npm run dev -- generate examples/basic.yaml --preview   # ビルドせずに実行
npm run check    # 型チェック + lint + テスト
npm run format   # 整形と自動修正
```

## 既知の制限

- 壁の側面は高さ1マス固定です
- A1(水・滝)のオートタイルは床・壁の指定先として想定していません
- ツクールMV/MZの実機エディタでの表示確認は、利用するタイルセットごとに行ってください
